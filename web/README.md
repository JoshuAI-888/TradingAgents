## Layout
```
web/
  worker/tradingagents_worker/     background worker (Render Background Worker)
    config.py      env settings (no secrets logged)
    db.py          Supabase REST access (service role, RLS-bypassing — worker only)
    queue flows    claim_job() RPC → run → persist → finish (FOR UPDATE SKIP LOCKED)
    runner.py      StubRunner (offline, deterministic) | EngineRunner (tradingagents 0.5.1)
    events.py      job_events emitter → Supabase Realtime → portal live view
    settlement.py  owned settlement ledger: +5d/+30d vs benchmark from price_bars
    discovery.py   Market Pulse sweep: screens/news/calendar/watchlist (~7 moomoo calls)
    moomoo.py      cloud REST client: Ed25519 signing, path-template budget (30/min),
                   HTTP-200 rate_limited handling, snapshot/screen/kline/find-news
    ttl_cache.py   vendor TTL choke point (quotes 5m · news 1h · ohlcv 1d · funds 7d)
    service.py     worker loop: claim → run → persist (runs/reports/decisions/memory/
                   settlements) + crash rehydration (running→failed on boot)
    settlement_cron.py / discovery_cron.py   Render cron entry points
    tests/         offline suite (fake Supabase, stub graph — no network, no keys)
  api/tradingagents_api/           FastAPI (Render Web Service, also serves the portal)
    main.py        /api/health /api/analyses (idempotent enqueue) /api/analyses/{id}
                   /api/decisions /api/candidates /api/meta + cron-gated queueing
    static/        portal SPA (Market Pulse · Analyze floor · Ledger · System)
deploy/supabase/0001_init.sql      base schema (31 tables, RLS, queue RPCs)
deploy/supabase/0002_product_deltas.sql   qc/evidence/quotes_realtime/budget/candidates
render.yaml                        blueprint: web + worker(+10GB disk) + 2 crons
```

## Go-live steps (owner + ZCode)
1. **Supabase**: create project (region ≈ Oregon) → SQL editor → run `0001_init.sql` then
   `0002_product_deltas.sql`. Copy project URL + service-role key (never anon key here).
2. **Set env** (dashboard or Render MCP): `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`,
   `WORKER_STUB_MODE=1` initially; `CRON_SECRET` is auto-generated by the blueprint.
3. **Deploy**: Render → New → Blueprint → this repo/branch → apply. Verify:
   `/api/health` → `{"status":"ok","stub_mode":true}`.
4. **First run (stub)**: portal → Analyze → NVDA → Run. Watch the floor; check Ledger.
5. **Go real**: `WORKER_STUB_MODE=0` + `OPENROUTER_API_KEY` on the worker → rerun → real
   decision. OpenRouter auto-selects with cheap-mode defaults (quick+deep = z-ai/glm-5.3-flash,
   ≈$0.14/run); override `TRADINGAGENTS_QUICK_MODEL`/`TRADINGAGENTS_DEEP_MODEL` for premium
   (e.g. `openai/gpt-6-sol` deep + `openai/gpt-6-luna` quick, ≈$5/run).
6. **moomoo probe**: set `MOOMOO_APPKEY`/`MOOMOO_PRIVATE_KEY` on worker/discovery →
   run `python -m tradingagents_worker.moomoo_probe` (records tier + AU entitlement).
7. **Seed prices** for settlement: `price_bars` backfill (yfinance today, moomoo nightly
   batch) — cron `discovery_cron` handles candidates; OHLCV backfill is Phase-1 work.

## Design decisions in force (see MEMORY.md)
- Engine stays stock 0.5.1; product code only in `web/` (no engine edits).
- Worker owns moomoo (Ed25519 key worker-only); no OpenD, ever; HTTP-200 rate_limited
  is the retry signal; budget ledger keyed by path template.
- Stub mode is the default until an LLM key is configured — every pipe is testable offline.
- REVIEW/blocked decisions never enter the performance ledger (qc_verdict gates it).
