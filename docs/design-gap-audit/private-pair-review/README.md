# Private capture-pair review foundation

Local backend implementation adds `/api/research/pair-reviews` GET/PATCH and an additive migration. Review identity includes authenticated owner, versioned screen history key, immutable before/after IDs and canonical instrument code. Public Changes and general shortlist review remain separate. The API reuses actual comparison validation, rejects unavailable/incompatible pairs and absent instruments, validates active sessions and ignores no client-provided owner (extra request fields are rejected).

Revision zero creates a previously absent review. Updates require the current revision; stale creates/updates return conflict without overwriting the note. The database additionally validates complete, chronological, same-version captures and pair membership. Authenticated clients can read only their own reviews through RLS; writes and RPCs are restricted to the server service role, with SECURITY INVOKER and an empty search path.

Review state is loaded by a single SQL statement returning a JSON aggregate, avoiding mixed revisions across paged PostgREST reads. Review status is applied before comparison sorting/pagination, so an unreviewed lookup respects ticker/company search and the chosen pair even when 501 earlier companies are already reviewed. Scope is bounded at 40,000 stored review records and oversized/unconfirmed responses fail explicitly.

Evidence: 454 API/worker tests and 122 JavaScript tests pass. Six new HTTP tests exercise the real comparison path with controlled stored captures and authentication transport: independent pairs, stale conflicts, 503 recovery semantics, unreviewed search/pagination beyond 500 rows, verified second-owner isolation, revoked sessions, absent/incomplete pairs and private no-store responses. The rollback-only native PostgreSQL test actually creates the migration, executes CAS and the one-statement read, verifies chronological/incomplete/absent rejection, and switches authenticated owners to prove RLS separation. This is isolated PostgreSQL 16.14, not live Supabase/PostgREST/Auth acceptance.
